2026-09-10。主G和Mac检查包仍使用旧蝶；此处是独立组件与动作源，未接入App、未完成精修或AAA验收。

## 图稿、来源与取舍

[结构/动作目标图](structure_and_motion.png)由内置 `image_gen` 生成，[完整提示词](prompt.txt)、[出处和哈希](manifest.json)同目录。以旧六藏品图的机械蝶为风格参考；方形书及那些独立底座不再有效。所有图中尺寸只是设计目标，不覆盖共享底座契约。

生成图的近景铰链轴向与拆解图不完全一致，也没有可靠证明连杆运动闭合。实际实现统一为竖直翼轴，以固定长度四连杆解闭合；不按图片直接拼出悬空杆。保留四片刚性瓷翼、镍骨架、黄铜脉络、石榴红嵌件与头部。收拢、展开、起势、振翅和回落作为动作方向，完整运行时节奏仍未验收。

旧蝶实际App截图在 [baseline](../../../review/G_optical_curator/butterfly_r2/baseline/)。它们与历史的孤立模型图分别保留，不能混称最新App。

## 已制作的独立组件

- [可编辑源](../../../blender/collection/G_butterfly_r2.blend)，生成器 `build_butterfly_component.py`。未打开或覆写完整G动画源。
- 四组固定叉座、贯穿轴、止推垫片、带孔翼毂、曲柄和固定长度连杆。摇臂从叉座外侧绕出，固定横梁接到固定背架；驱动轴承有后侧支承，曲柄与连杆错层，端头改成带内腔的半球杯及球头/球头销。后翼沿后方错开0.055。
- 连杆长0.060、输入曲柄0.025、翼根摇臂0.022；输出角通过闭合解计算输入角。并非把一根杆任意拉长来追随翼根。
- 翼背增加贴合后表面的镍肋、带槽紧固件和边缘密封线。触角改到翼缘之外；尾部栖柱接上脚座，脚座盲孔按实际唱片凸台校准。
- 翼面由旧曲面翼算法改写，修掉原来环形起伏导致的皱褶，重新计算壳体法线；脉络和红色嵌件按实际翼面定位。红色区域改为沿翼缘的弧形嵌件。
- 六足带髋节/膝节并抓住栖架；为避免后翼收拢时切到股节，腿部改走后侧。原始两轮失败报告保留。
- 源内541帧、30FPS，涵盖休息、展开、起势、振翅、回落、收拢。动画只存在这个独立源；不是App实机演出，也没有新GPU特效。
- 最宽翼展约0.8847，高约1.001。参考圆盘D0.840仅用于源图对照，不导出为新的底座。最新组件约238344三角面、17个合并网格；小铆钉降低细分，新增细节没有恢复每个零件一个运行网格。

实际源渲染：[展开](../../../review/G_optical_curator/butterfly_r2/component_open.png)、[收拢](../../../review/G_optical_curator/butterfly_r2/component_folded.png)、[振翅采样](../../../review/G_optical_curator/butterfly_r2/component_beat.png)、[背面](../../../review/G_optical_curator/butterfly_r2/component_rear.png)。这些均为Blender源检查，不是生成图，也不是当前App。

## 检查范围

`drive_closure.json` 记录541帧、四组解析闭合，最大杆长误差约5.3e-9。只证明数学长度关系，不能替代实体装配/网格净空检查。

早期 `check_butterfly_component.py` 的37个翼面/身体姿态报告保留作历史。最新 `check_butterfly_hardware.py` 检查保存源的55个姿态，覆盖12个运动组对其他运动组和全部固定组件表面，未检出交叉。初次12对错误另存 `hardware_clearance_initial.json`，之后修正轴承支承穿入曲柄、横梁插入转动翼毂及触角擦翼。

`check_butterfly_player.py` 将独立组件放入主G实际“唱片1读取完成”的姿态，检查5个翼角×24个唱盘角，共120组合。首次发现脚座凹槽过窄碰中心凸台，随后按 `record_height_probe.json` 的真实射线高度修正：盲孔半径0.034，孔顶z0.027，安装偏移0.00125。标签支承面的间隙约0.00101，轴头顶面到孔顶约0.00445；当前120组合未检出表面交叉，见 `player_clearance.json`。

这些检查不认证同一刚体组内部的装配接触、所有实体包含关系、全运动范围的精确最小加工间隙、实际取放/形成/回收/取消流程或App质量。物理配合名义值与最终源/GLB哈希见 `rear_and_mount_report.json`。新[翼根展开近景](../../../review/G_optical_curator/butterfly_r2/hinge_detail.png)、[收拢近景](../../../review/G_optical_curator/butterfly_r2/hinge_folded_detail.png)显示错层连接；最新[脚座盲孔](../../../review/G_optical_curator/butterfly_r2/mount_socket.png)对应最终源。翼根和整体图在最后一次盲孔扩径前渲染，后续变化只在底面孔内，其他可见结构保持。

组件GLB/JSON位于 `app/assets/collection/components/G_butterfly_r2.*`。当前JSON使用 **Blender Z-up**，是作者侧数据，尚无Godot运行时适配/形成路径。不得把它直接当已有主G内容metadata替换。

## 下次从这里继续

1. 从已有独立源和metadata生成Godot姿态数据与四连杆驱动适配。固定长度使用最新0.060，连杆局部Y保持竖直、球杯开口向下；避免导入时弄错Z-up/Y-up和连杆滚转。
2. 制作沿翼根到翼尖的有序形成路径，结合已保存分镜和专属光纹。翼根、连杆、翼面形成顺序与展开时序必须一致。
3. 保留主G当前源及动画，建立独立运行时候选，以安装偏移0.00125在同一真实底座/唱片上检查；不要直接覆盖主模型。
4. 完成实际材质/灯光/展开振翅/形成回收/中途取消/操作及Mac检查，再接下一件藏品。整G小字、性能和完整源特效仍在队列中。
