# 月光演奏的膜片响应

先有内置生图 `music_response_r1.png`（提示词 `PROMPT.md`），再将真实录音的强弱接入既有 Blender 膜片/悬架形变。图中的夸张重影、末格发光卡扣不作为制作内容；不改瓷口沿、护网、三片卷收路径或共同底座，不使用生成音符。

## 实际驱动

`tools/music/build_moonlight_envelopes.py` 从当前 manifest 的三个原始音轨解码双声道功率，20 ms 居中 RMS 窗口，每 10 ms 取样。三乐章共用全曲 P99 标尺及 -58 dBFS 底噪门限，避免把轻柔第一乐章放大成第三乐章一样强。原录音不改写；这是一条为视觉表现制作的包络，不是空气压力或扬声器位移的物理模型。

独立数据 `response_envelopes_r1.json` 绑定三个音源哈希。`i_music_transport` 沿实际输出时钟采样，所以跳转、跨章和谱面共用同一时间源，不另跑节拍计时器。已停止、暂停、结束时输出零；正常停止按实际音量淡出同步减小负载。

`i_mouth_response_rig` 将音乐强弱输入现有悬架，目标最大行程 0.0024 场景单位。现有阻尼允许小幅自然回弹；三根触须、膜片前压座一起轴向运动，后座和外圈固定，所有几何与 Pressure/Rebound 键保留。音乐中没有机械提示音或额外回声光圈。暂停保持谱面位置，膜片逐渐归位；停止后先收谱，待悬架卸载才合口。

- `review/I_refinement/moonlight/current_mouth/response/envelopes.json`：三个音源、制作脚本与数据哈希；第一乐章开头三秒没有响应。

- `current_mouth/controller_qa.json`：真实 transport 暂停与跨章跳转、停止中重播、迟到结束回调、淡出合口，并增加暂停归位和音乐时间源取样检查；Dummy 音频，未宣称听感验收。

## 录制异常独立记录

第一条 MovieWriter 录制 `take_r1` 被拒用：两次 Metal fence 超时；同一第三乐章从 frame720→780 的音频时钟跨了 53.07 秒，脚本仅前进 1 秒。引擎总结 1441 帧，AVI 实际解出 4566 帧、76.1 秒。不能将其发布为 24 秒同步演示。原数据、渲染帧、log、ffprobe 和 rejected.json 都保留。此次同时在进行原生窗口操作；这只是相关条件，尚不能断言是根因。

Movie Maker 本来使用固定帧率的非实时音画录制（[Godot 官方说明](https://godotengine.org/article/movie-maker-mode-arrives-in-godot-4/)）。隔离重录 `take_r2` 不再并行做窗口操作，但又发生 Metal 超时，已停止该自有录制进程并保存记录。因此不能把问题归结为 Computer Use 并发。接着保持同一 Metal/Forward+、分辨率和材质，仅按当前 Godot `--help` 的录制提示关闭本次捕获进程的 vsync，输出新 `take_r3`；实际 App 设置不改。必须检查实际帧数与同章音频增量后再采用，不因进程退出 0 接受录像。
