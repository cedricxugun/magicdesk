# 用户反馈：运动时像透片/有洞，到位后中心触须穿帮

此反馈覆盖“单片已通过几何检查即可继续扩展”的接续；先完成这两项实际画面修复。

## 定位与修复

变形源与数据哈希通过仍不等于 GPU 画面正确。原导入启用了基于 REST 网格生成的自动 LOD。纯色 GPU/完整网格对照中轮廓差异很小，但保留同一模型、相机、材质、灯光，仅关闭 LOD 后，运动片入口附近的明显三角斑块/破面感消失。单独去掉 shadow_mesh 不改变结果，因此没有把当前问题归咎于阴影网格。记录在 review/I_refinement/part_a_mouth/shutter_r2/tongue_probe/raster_audit/，含 lit_baseline、lit_no_lod、lit_no_shadow 与 lit_differences.json。

正式绑定现在为这两张变形薄片保留完整的原始顶点、索引和行坐标数据，重建无自动 LOD 的渲染网格。只改变这两张薄片，未通过关闭全场阴影或修改透明度来掩盖问题。背层从近黑色改为镍材质，以免翻卷后呈现黑洞般的表面。

中心三根红尖杆此前沿 X 方向从头部侧面伸出，和原图的正面轴向插座不符。已按喉口的向外轴线（Blender 局部 -Z）重做三根杆、独立孔座、沉孔及连续轴颈；保留与膜片节点的父子关系。旧正 X 相机保留作前后对照，另提供更接近原图的负 X 侧向视图，不能以换相机代替检查。

## 验证边界

几何、数据和实际着色画面分别核对。新三孔头部布尔产生的重合接缝点已焊合；源网格封闭检查重新运行。卷收/回程、256 个插值中点与源/纹理位置对照仍需与最新 build.json 同哈希。

预览改用带版本标识的新 MP4 文件，不再覆盖已经打开的视频。仍是单片机构与中心连接的局部候选；另外两片及完整驱动机匣未完成，主 App I 尚未替换，也未宣称 AAA 验收。

Godot 对自动 LOD 和 shadow mesh 的处理必须在实际渲染中检查。ArrayMesh 文档说明 shadow mesh 的顶点必须与主网格匹配；它在本次 A/B 中不是已证实的主因：https://docs.godotengine.org/en/4.7/classes/class_arraymesh.html
