# R54 连续音乐展示，停止默认插入暂停测试

用户询问音乐为何暂停再继续。查明此前25秒录像脚本在第450帧/15秒调用pause，第510帧/17秒resume，并在20秒再次暂停以收谱合壳。这是演示脚本的人工测试动作，不能作为正常播放表现。

`tests/collection/i_nautilus_mechanism_take.gd --music-review` 现在默认连续模式：3秒开壳/显谱后，从录音开头起播；63秒影片内继续播放约60秒，不插暂停、跳转、停止或收壳，影片结束状态仍在播放。实际播放器的用户暂停/恢复控制未改。独立功能测试须显式 `--test-pause-resume`，片头标明“功能测试”。

最新媒体：`review/I_refinement/nautilus_r1/cap_trim_r53/continuous_r54/moonlight_continuous_r54.mp4`。当前模型包含R53新托边，透明谱面无黑底。实际1890帧/63秒。

有效检查为 `validation_audible.json`：状态只有stopped→playing；原15、17、20秒和后续33、53秒的五段音轨均与原录音吻合，相关性约.993–.9998、时间偏移小于.02秒。时钟漂移约.04秒以内，最终播放帧与截图匹配。初次validation.json失败是因为比较了原录音自身静音的第2秒；保留失败报告，验证器现在从首个有声音的源窗口进行相关性检查，而不是把零波形算作同步通过。

此为第一乐章连续片段，不是完整三乐章播放或逐音谱时校准。录制进程退出时出现2个资源仍占用的警告，日志已保留，原因待单独查明，不称原生生命周期通过；音视频检查与该退出问题分开。主App尚未更新。
