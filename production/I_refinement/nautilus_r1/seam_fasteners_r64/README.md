# R64 可分离夹环紧固件与真实拆卸依赖

**两版均为候选，未替换可靠整机R61/0ba13905，未接入主App。** R63的03号动画源和R60/R62运行时保持。本轮没有宣称夹环已经可打开，也没有新安装包。

## 新件

原 `IC1_SeamCrossBolt_±1` 把两端头和杆体布尔成一个物体，无法真实退销。R64保留正端头，重做另一端带实际外螺纹的杆端，新增独立 `IC64_SeamSocket_±1`：内螺纹、盲孔、外端内六角和倒角。负端帽局部加深到.012，名义径向配合间隙.00025，盲孔与内六角之间保留.0007壁厚；没有改变口部、底座或夹环本体位置。

原同向候选源 `I_nautilus_seam_fasteners_r64.blend` / **bb7d0589**；定向试验源 `I_nautilus_seam_fasteners_r64b.blend` / **2441d501**。后者把+1侧整个杆/端帽绕真实中心X轴旋转180度，未镜像螺纹、未改其几何，以尝试相反退销方向。两者都保留，不将较新文件自动当作已通过源。

构建中除两根原销杆外，1233个原网格的顶点、三角、法线、UV、形变、材料索引和变换保护通过；两根新杆/两端帽均闭合、正体积、自接触0。杆与端帽初始配合无所查相交。这些只证明局部几何，不等于整机可拆或实际承载认证。

## 路径结果

`release_check.json`与`oriented_r2/release_check.json`均为 **passed=false**。

- 两个端帽按真实螺纹螺距旋出，12组非整数转角/位移采样未见未允许的碰撞；带名垫片仅按明确平面半空间容差记录装配接触。
- 原同向销杆的+1侧向上退，会撞01/02固定瓷壳。
- 反向布置后同一侧向下退，仍撞02固定瓷壳。它不是简单换个方向就能解决，不能删掉壳片或豁免这些碰撞。

## 已确认的拆卸依赖

R61的`metal_supports.ports`显示：Leg01穿口跨01/02壳片，Leg02穿口在02壳片，两根支柱实际穿过这些壳体。R18制造代码还把脚部FootPin的两端帽并入销体。因此下一步需先处理支柱真实销/端帽和支柱穿口，释放支柱/穿口后再移开02壳板，最后完成夹环退销与口部退出。

这是一条待逐段验证的装配依赖，**不是已通过的支柱拔出轨迹**。腿体、下眼和密封圈尺寸要用实际几何复核；不要因为名义孔径大于部分杆径就宣称整体可穿过。需要考虑穿口内衬/密封圈、脚座/上耳轴的先后顺序和仍保留的口部承接。

## 实际图与检查

`oriented_r2/views_r3` 为当前有效局部实际图：装配、端帽旋出、销杆分开、内螺纹及外端内六角。它隔离真实导入件，只展示-1侧的几何/材质；不能拿隔离拔出图冒充+1侧在完整装置中已通过。

前两轮图像已生成，但退出时出现Godot light/geometry unpair错误，日志保留，不记为干净生命周期通过。第三轮只把需要的真实零件保留在诊断场景，再创建灯光并分阶段释放，日志干净。该修复仅限检查场景，不是主App退出验收。

`oriented_r2/light_qa.json` 使用独立R36组件重新检查12片膜片的实际导入缓冲/变换、响应和灯光释放，通过其范围。没有改R63绑定签名来跳过兼容检查；当前03动画仍只认已验证的R61主体。

本轮结构工艺沿用既有C1夹环设计和R63拆解方向，没有新增未经验证的长轴、没有外部图片API调用。仍需完成支柱/固定壳/夹环解锁及完整拆解、侧边回折/工艺、全曲逐音校准、性能和F/I/J/K/L/M/N/最后G全队列。全目标active。
