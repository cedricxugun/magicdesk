# 过载、中心机构与按钮修复 · 1.3.2

## 过载时机

机械过载是7秒，但旧核心效果只有4.6秒包络，强电弧还在2.25秒之后停止。现核心、支柱、底座、外壳标志和轨道粒子统一读取主状态的7秒进度，使用同峰的增益，3–4秒最强，3.5秒达峰。电弧先短蓄能，随后持续长放电，高潮后再退潮。

实际画面：[高潮](../review/mechanism_fixed_overload.png)，完整演示：[mechanism_fix_demo.mp4](../review/mechanism_fix_demo.mp4)。

## 陶瓷与拆解结构

白色圆盘是低位电极的陶瓷绝缘支座。原`P_Thermal_Valve_1/2`处于花瓣3/4的运动区域，闭合与展开时会穿壳，其中一组还与连杆相交。

现在改为固定在中央平台的短馈通端子：瓷盘半径0.09、厚0.026保持，四片轴向中心为1.231/1.278/1.325/1.372，顶部针在1.47。短金属座替代旧长真空管及垂下的铜线；高侧阀门0保留。电弧接点按新针头坐标同步。

中心拆解先把转环对齐，在0–0.18拆解进度完成；然后抬升0.52，再沿共同法向以0/0.30/0.60/1.00分层抽出。晶体与完整格架作为一个核心总成保持相对姿态，支撑轴先抽离再侧移。组装沿相同分段路径逆行，避免原来的交叉拉扯。

验证：21组正常姿态中短馈通与壳片/连杆/转环/轴均无相交；12组中心与外侧部件扫掠检查无相交；后半段及完整拆开没有环与环、核心与环、晶体与格架的新交叉。配对轴座与环体的正常装配接触保留，不把它们误称为全部零相交。原始数据在`center_repair_candidate.json`和`center_external_candidate.json`。

Blender源文件、GLB和机构数据已同步。现有主开瓣与连杆时序保留，源文件只更新中心拆装段及局部端子几何。70部件、7按钮、7张内嵌纹理与278个带顶点AO的渲染primitive保留；静态GLB核心发光参考值恢复为0.8，实时核心仍由效果材质控制。

实际画面：[正常展开](../review/mechanism_fixed_open.png)、[分层拆解](../review/mechanism_fixed_exploded.png)。

## 组装与关闭

用户补充“先收拢、熄灯，再退出”，与正常关闭流程一致。自动测试未复现组装分支主动退出，不能声称找到崩溃根因。旧圆柱命中半径0.158，高于可见帽面的0.113，并伸出可见表面；现按实际帽面进行射线圆盘命中，关闭按钮只接收其真实帽面内的点击，组装与关闭的提示及指示灯也明确分开。

153个按钮中心、帽面与关闭外圈位置检查通过。最终EXE中分别从全开、开到一半、拆解中途、过载中调用第5个按钮，均完成组装/收拢后继续运行。只有最后主动点击第7个按钮才进入关闭流程。`assembly_fixed/native_verification.txt`保存四项存活记录；事件日志确认这些组装操作均为index4。

全功能实机加录像检查2477帧无空白、无透明合成错误、无透明或实体点击失败；独立组装测试2424帧继续通过。对应目录为`mechanism_release/`与`assembly_fixed/`。

最终版不录屏的全动作性能检查平均59.63 FPS、中位16.66ms、P95 18.45ms；开蛋5秒区间中位17.108ms、P95 20.745ms、最长25.408ms。完整记录在打开前的闲置期还出现一次114.585ms长帧，未归因，不能宣称整段零波动。记录见`mechanism_performance/frame_trace.csv`。
